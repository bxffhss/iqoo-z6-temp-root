用 Python 脚本给源文件做"替换一段/插入一块"的改动时：**只能按唯一字符串定位，并且在写盘前断言命中数**；
按行号切片(`L[a:b] = …`)迟早会把不该删的删掉。

**Why:** 2026-09-28 在本项目里我用 `L[a:b]` 插一段判据代码，锚点 `int ok = 0;` 在文件里出现了多次，
`b` 又是"下一次出现的很远的那行"，结果一次误删了 `cm57/pr.c` 里约 1100 行（整个 hammer 主循环），
幸而 Qoder 在 `<LOCAL_MEMORY_PATH> 下按 `<文件ID>@vN` 存了每个
工具编辑版本的全文，取回最近的 v28 才恢复（**脚本/`python -c` 直写文件不进这个历史**，所以
"Edit/Write 工具之后再跑脚本"时，能恢复到的正好是工具编辑的那一版）。

**How to apply:**
* 定位串必须先 `assert s.count(anchor) == 1`；要取"第 N 次出现"就把所有命中打印出来人工确认。
* 插入/替换的区间两端都要断言（`b > a`、`b - a` 在一个合理范围内），否则宁可不动文件。
* 一次性脚本写到临时文件（如 `cm57/_blk.txt`）再 splice，用完删掉；别把中文注释塞进 heredoc，
  `\n` 会被解释成真换行把 C 字符串字面量截断（本项目踩过两次）。
* Windows 上 `python x.py` 打印中文/箭头字符可能 `UnicodeEncodeError: 'gbk'` —— 设
  `PYTHONIOENCODING=utf-8`，并且**先写文件再 print**，否则 print 抛异常会让人误以为写盘也失败了。
* 改完立刻跑一次编译（或语法检查）当作第二道判据，别把坏文件留给下一轮。
* **锚点"唯一"不等于幂等**：脚本第二次跑还会命中同一个锚点并再插一遍。2026-09-30 布局补丁被打两遍，
  `struct module` 从 960 变 1024，症状长得像"厂商加了字段"，害我据此重推了一遍结论。
  ⇒ 每个改文件的脚本开头加**幂等闸门**（"目标文本已在文件里就跳过"），并打印"跳过(已打过)"。
* **写"桩/转发"时同样只认唯一锚点 + 让编译器核对签名**：桩文件必须 `#include` 它要实现的那个头，
  否则原型差一个参数也没人报（本项目 `handle_sepolicy` 就写成三参，静默 ABI 错）。
  反过来也要提防**函数式宏会改写声明**（`extern int f(args);` 被展开成定义），
  ⇒ 别名只用于"数据对象"，函数改用同名转发函数。
* **★对"权威交接文档"绝不做整文件重排/全局行过滤（2026-09-30 烧掉一整份判据链的格式）**：
  我为了移动一个章节，顺手写了 `out=[l for l in out if l.strip()!=""]`，
  结果把 `kmod/ROUTE-B-OFFSET-INVERSION.md`（1700+ 行判据链）**所有空行删光**，
  markdown 段落全糊在一起。更糟的是 **file-history 里救不回来**：
  那里只存 **Edit/Write 工具编辑过的文件**的整版快照，我用 `python` 直写的那个大 .md 没有快照
  （grep 到的全是同目录里 3–4KB 的其它文件片段），只能靠"标题/代码栅栏前补空行"的启发式重写回去。
  ⇒ 规则：① 改文档只做**插入式**编辑（Edit 唯一锚点），不要"读全文→重排→整文件写回"；
  ② 真要全局过滤，先把原文件 `cp` 一份带时间戳的副本；
  ③ 别指望 file-history 能救 `python`/`sed` 直写的文件 —— **它只覆盖工具编辑的那一版**，
  所以"先 Edit 一版再跑脚本"时，能恢复到的恰好只到上一次工具编辑为止。
* **推导出来的常数也要写成断言**：把"树值 + δ"直接当事实用会算错（我把 pid/comm/seccomp 写成树值，
  负长度数组断言当场点名）；断言 = 把猜测关进闸门。
* **对象式宏别名之前先确认那个名字不是类型名**：`#define selinux_state (*p_selinux_state)` 会连
  `struct selinux_state` 里的 **tag** 一起替换（预处理不看 `struct` 关键字）⇒ 整个头文件崩成
  一串看不懂的语法错。同一个坑的另一半是 `__typeof__(名字)` 只在该名字**有公开声明**时可用
  （内核内部符号/static 函数取不到 ⇒ 只能从定义行逐字抄，别凭记忆）。
* **★补丁脚本"跑完"不等于"改到了"：必须回读命中计数，别只看构建 RC=0（2026-10-01 两次）**
  ① 脚本里一处 Python 字符串续行写错 ⇒ **SyntaxError 在解析阶段就炸**，三处编辑一处都没进源文件，
     而构建照样 `RC=0`、照样出一个能过闸门的 `.ko` —— 我差点把"没有那几行打印"的产物推上设备；
  ② 多行锚点（我按整块文本拼的 anchor）命中 0 次或 2 次 ⇒ 脚本按规矩拒绝改动，但**只看 RC 就会漏看**。
  ⇒ 规则：每次远端构建之后**固定读日志的"补丁段落"**（`+tag` / `=已有` / `!!命中 N 次`）与
  校验段的 `grep -c <新字符串>` 计数（应当逐条 =1），再跑离线闸门；
  计数缺一条就当**产物无效**，回去修锚点而不是"先发一发看看"。
  顺带：非 ASCII 的长段文字用 Write 落成临时文件再 `cat >>`，别用 heredoc（会被截断且报错很难读）。


**★2026-10-07 现场：我把项目记忆的 `MEMORY.md` 索引写成了 0 字节**（改法=脚本 `read → split → join → 整篇 write`，而 `MEMORY.md` 是**CLI 自己也在维护的文件**：它那边正在重写时我这边读到空串，再写回去就是空文件；各条记忆文件本身没伤到，但索引里的 dense hook 只能靠上下文重建。）
**规矩（改共享/索引类文件一律照做）**：① 单行编辑优先（Edit 工具或精确 replace），**不要 `read→整篇→write` 往返**；② 必须整篇写时，写前先断言 `len(新)>阈值` 且**每个应出现的条目都在**（我那版重建脚本就是这么保住 21 条齐的）；③ 写完**必须回读核对**（字节数、行数、条目清单），不核对就等于没写；④ 发现被外部改过（系统提示 `file was modified since it was last read`）就当它是**并发写**，重读再改。
**追加(2026-10-12)：`s[i]` 与 `s[i:]` 只差两个字符，能把一份 91 KB 的交接文档截成 3 KB——而救回来靠的是"写之前先断言字节数"**
我用 python 往长文档里插一节，写成 `s[:i] + new + s[i].replace(旧标题,新标题)`——`s[i]` 是**单个字符**不是切片，于是锚点之后的全部内容被丢掉，只剩 3,990 字节。
⇒ 三条规矩：**(1) 文档级插入优先用 `Edit` 工具(它按唯一锚点替换，不做索引运算)**；非用 python 不可时，写成 `s.replace(anchor, new+anchor, 1)` 并先 `assert s.count(anchor)==1`，**永远不要手算下标**。
**(2) 写盘前必须断言"新内容比旧内容长"**，且**按字节比**：`len(s.encode('utf-8'))`。我这次两条都撞上了——第一次没断言(文件被截)，第二次断言用了字符数(`len(s)`=56,936)去比字节阈值(85,000)，**断言假失败**反而救了我；同一份中文文档 88,307 B / 56,936 字符，两者差 1.55 倍，混用必错。
**(3) Qoder 的 `file-history/<session>/<uuid>@vN` 存的是"每次编辑之前"的副本**，所以最新那个快照往往正好是"被改坏前"的完整状态；找回方法：`grep -rl "<文档里独有的那句话>" file-history/<session>/` 再按 `mtime` 排序取最新，整文件 `cp` 回去，然后**重放**我本来要做的改动(改动文本要能重建，别只留在 shell 历史里)。

★**同一族还有一次是改文档不是改代码**(2026-10-16 00:3x，临时 root)：为了把两节的时间戳从近似值 `00:4x` 改准成 `00:2x`，我用了一次**全局字符串替换** ⇒ 连带改了 5 处**历史节名与交叉引用**(10-04/10-13 那几节)。发现靠的是改完 `grep -n` **数命中面**而不是只看我要的那节(多出来的行数就是警报)；修法是去会话的 `file-history/` 里按特征串定位改动前快照、**拿快照当基准逐行比对**，再用唯一锚点定点回退。
⇒ 规矩不变但范围扩大：**任何"全局替换"都只允许作用于本轮新写的行；改文档里的编号/时间戳/标题一律定点改，改前先数命中面**。
★另一个新坑：**判定"哪些行是历史内容"要以快照为准，别凭记忆**——快照里 2026-10-02 那一节本来就写 `00:2x`，凭记忆把它也"修"回去就是第二次破坏(复原时我差点这么干)。


### 补充（2026-10-18 15:4x）：**`grep -c` 数的是"命中行数"，不是"出现次数"** ⇒ 它不能当"唯一锚点"的凭据
我这次用 `grep -c "凡是写死 10319 …"` 得到 **1** 就当锚点唯一，python 里 `assert s.count(...)==1` 却可能炸（同一行出现两次时 grep 仍报 1）。反过来也一样：一行里两处都要改时 `replace(a,b,1)` 只改第一处，剩下的那处仍是旧值而 grep 看不出差异。
**Why**：交付台账是"一行塞几十条事实"的体裁(DELIVERY 的资产行、runbook 的编号节)，**同行重复**是常态；"行级"计数在这种体裁上系统性偏乐观。
**How to apply**：脚本改文档前用 `python -c "print(s.count(a))"` 数**出现次数**；写完紧跟一次 `grep -o` 数或 `s.count(新值)` 读回；长 CJK 锚点失败时**先缩短再验证**（本次改用 `都要现取）。` 这种短锚一次通过）。

★**2026-10-23 新增一族：old/new 只差"换行"的 Edit 会把两行粘起来，把文件当场改坏**
我用 Edit 做一次"看起来零改动"的确认性编辑，new_string 少了一个行尾换行 ⇒ 下一行被并上来，
`FILES = [...]TS = re.compile(...)` 直接 SyntaxError；**同轮还有第二次**："那个文件与上次读取时相比已被修改"的提示我没停手，
Edit 照样落在没读过的内容上（本轮靠 `assert 命中数==1` 与紧跟的编译检查抓到，没流到交付件里）。
**Why**：Edit 是按字面替换的，**换行与空白也是字符**；"只动一点点"恰是最容易吃掉结构字符的那类操作，
而"看着没事"的坏文件会一路活到下一次真跑（本项目所有闸门都在读这些文件）。
**How to apply**：① 凡 old/new 的差异**只在空白/换行** ⇒ 干脆别发这个 Edit；要插入就显式带换行、并把锚点后的内容一起写全。
② 每次编辑**可执行文件**（.py/.sh）之后**立刻** `py_compile` / `bash -n` / 设备侧 `sh -n` 过一遍，把它算作编辑的一部分而不是"下一步"。
③ 出现 `file has been modified since your last read` 就当**并发写**：先重读再改，别连着发 Edit。
④ 生成器/脚本类文件改完要**跑它自己**一次并看输出（本轮 `w544`、`w558` 就是这么验住的），只读内容顺眼不算验证。

⇒ 补救也照同一条：覆盖掉的文本我按 `§6.407`／`§6.404` **重建**，并在两条里明写"本处以 md 为准，不要以此处为唯一来源"——**不假装复原成功**。


## 同一族的第三种形状：自写的**临时定位脚本**也要带护栏（10-24 一手）
调试时随手写的 `python - <<PY` 脚本**没有牙**：我写"找出某串在文档里出现几次"的小脚本，`s.find(...)` 之后忘了 `pos = i`，**游标不前进 ⇒ 死循环**，而它被系统当成后台任务挪到后台继续跑，**输出文件灌到 5 GB 才被杀**。文档没被写过、没有实际损失，但这是"临时脚本比正式脚本更危险"的一手证据。
⇒ 三条硬规矩：①**任何自写的循环都要有退出条件**（写完立刻看一眼游标有没有前进）；②**临时脚本一律带 `timeout`**（本轮起统一 `timeout 60~150 python -`）；③**能不用循环就不用**——数出现次数用 `s.count(x)` 一行，不要用 `find` 手写循环；要遍历用 `for` over `re.finditer`。
★这与"唯一锚点""期望值由来源现数"是同一条病：**我给脚本写的判据/游标，本身也要被当成会坏的东西来对待**。


## 「fail-closed 也得是全量的」——10-24 自己写的文档同步器只回滚了一半
`w758_docsync10.py` 第一版按文件循环：对每个文件「核锚 → 不符就 exit → 符合就写」。结果 **DELIVERY 六个锚全中并已落盘、下一个文件 W345 才发现锚写错** ⇒ 所谓"一个字都不写"只对没写的那个文件成立，**已经写过的那半个改不回来**，第二次跑就变成"锚不符"死锁（我以为是幂等的）。
⇒ 两条规矩：**①两阶段**——先把**所有**文件的所有锚核成「待做」或「已经做过」，全部通过之后再统一写；**②重跑要能识别"已做过"**（`new` 命中数==期望 ⇒ 跳过并明写"已做过"），否则一次半途失败就把工具变成不可重入。
★附带同一条族的两个小坑：占位符守卫别用通用串（`count("@@")` 被文档正文里的 `@@@PKGS` 误报，要盯自家 token）；**判据正则里"版本号"这类名字的格式也是隐含假设**——`kernelsu_rc[0-9]+\.ko` 认不出 `rc74b`，让三处检查**连反夹具一起静默失效**（读成"空"而不是"红"）。


## 「回填占位符」这一格有两个新形状（10-25 第 54 发，同一轮两次）
① **替换用的 token 名与常量名对不上 ⇒ 静默不替换**。我用 `re.sub(r'^'+k+r' = "@@'+k+r'@@"', …)` 把哈希回填进 `w793_docsync12.py`，`k` 是变量名(`PLAN`)而文件里的 token 是 `@@W791@@`——**一条也没换成功，而且不报错**；文档照跑，正文里留下 9 处 `@@W791@@`/`@@W786@@` 这类字面量。
⇒ 规矩：**回填之后必须"读回落点"而不是"读回工具"**——对目标产物断言 `re.findall(r'@@W[0-9]+@@', 文档) == []`（token 用自家前缀，别用裸 `@@`，正文里本来就有 `@@@PKGS`）。工具自己 print 的 dict 只证明"我算出了哈希"，**不证明文档里出现了它**。
② **幂等判定要覆盖"顶替/改标签"这一类操作**。插入类认"新节标题已在"就够；但 `replace(旧标签 → 新标签)` 第二次跑时**旧标签必然命中 0**，我的核锚逻辑把它当失败 ⇒ 整批 fail-closed 卡在一处"其实已经做完"的改动上。
⇒ 规矩：每个操作类型都要有自己的"已做过"识别式——插入＝新节首行在；替换＝**新文案在且旧文案不在**；追加＝节标题在。并且**替换/回填这类动作要设计成可补写**（先跑插入，再单独跑一遍"把残留 token 换成实值"的补写步），别指望"改常量＋重跑"会自动补写已插入的小节。
③ **10-25 第 57 发之后又一格：我用 `s.replace(A,B)` 修自己的自测件，A 早已不匹配 ⇒ 命中 0 次、文件没动，脚本照打 `[ok] …已落`**；下一轮重跑那个自测才从"那格仍然红"里发现。⇒ 规矩：**replace 前后各断言一次**(`assert s.count(A)==期望次数` 且 `assert B in 改后内容`)，命中数期望要写死成 1(或 0，用于幂等)；而"改动是否生效"最终**由产物的新行为证明**(重跑那个自测/闸)，不由脚本自己那句 print 证明。★同一轮还有一格同族：登记进文档的 **md5 我凭印象抄**(`w821` 抄了自己摘要里的旧值)，靠"拿仓库当正对照"的文档闸才抓到 ⇒ **可复算的量(哈希/字节数/条数)落笔前现场重算一次**。


## ★★2026-10-27 一手：**脚本进程内的 count 不是落盘证明**；同一份"合并跨行字符串"我连跑三次都自称成功，而文件从头到尾没修好
背景：我给 `kmod/w986_polround.c` 插了几条 `pr_info`，python 串里写的 `\n` 被当成**真换行** ⇒ C 字符串字面量被截断（`missing terminating '"'`）。之后我写了三次"把跨行的字符串拼回去"的修补脚本，每次都打印 `合并处数=6`，**下一次从盘上重读还是 12 行奇数引号**；第三次的行级拼接还把 `rt_stage = 2; rc = p_read_policy(state, &img, &len);` 整段**重复插了一遍**（语法合法，编译器不报，只有人读 diff 看得见）。⇒ 那一版 `.ko`(`f116eb39…`) 的"仓库＝产物出处"链当场断掉。
**Why**：脚本里"我拼了 `out` 列表"和"文件真的变成这样"是两件事；`count()`/`assert` 跑在**内存对象**上，而破坏发生在写盘环节（同一轮还叠加了 CRLF/编码/`newline=` 参数的噪声）。
**How to apply**：
1. **改源码的脚本一律三段**：`写盘` → **重新 `open()` 该文件** → 数标记出现次数（期望值写死）→ 再跑编译/`bash -n`。**没有"重开文件再数"这一步，就当没改过**。
2. **绝不用 python 串里的字面 `\n` 去拼 C/shell 字符串**：要么 raw 串/双反斜杠，要么**用 Edit/Write 工具直接写整段**（本项目 CJK 文档/源码里这一步已经第三次出事）。
3. **插入式改动必须防重复**：新文案已在 ⇒ 跳过并打印"已做过"；否则第二次跑就是把同一段代码叠两遍（这形状在文档、ko 布局补丁、这次的 init 上各出过一次事）。
4. **产物一旦与源码 md5 链断开，就要在台账里明写"这一版断了，别拿它当已核过的出处"**，不要靠"我记得我改了什么"蒙过去。
