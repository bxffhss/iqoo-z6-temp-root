## 1. 补丁到底改了什么 (primary source: git.kernel.org stable.git, 已取原文)

```

-	__inet_csk_reqsk_queue_drop(sk_listener, nreq, true);
+	__inet_csk_reqsk_queue_drop(sk_listener, nreq, false);
```

机制(v6.6.90 源码逐行核对):migration 尝试时 `nreq = inet_reqsk_clone(req,...)`, 随后 `timer_setup(&nreq->rsk_timer,...)` 且 **`req = nreq` 别名化**。成功分支里 `mod_timer(&req->rsk_timer,...)` 重新挂的是 **nreq 的 timer**;若 `inet_ehash_insert()` 失败,helper 第三参 `from_timer=true` 会**跳过** `if (!from_timer && timer_delete_sync(&req->rsk_timer))`,而 `reqsk_queue_unlink()` 里的 `timer_pending() && del_timer_sync()`(正是 `83fccfc3940c` 那行)因 timer 刚被 mod_timer 而 **不为 pending** ⇒ 不删。接着 `no_ownership:` 标签执行 `__reqsk_free(nreq)`(即 `kmem_cache_free`)——**提前被 free 的对象 = 新克隆的 nreq**,**推迟它的是 nreq 自己的 rsk_timer**。之后 timer 到期,`reqsk_timer_handler()` 在已释放内存上跑:`from_timer()` 反推对象基址 → 读 `req->rsk_listener` 并解引用(野指针)、写 `req->num_timeout`、`mod_timer()` 把 timer base 指针与 expires 写回对象内固定偏移。所以 stale access **既有 read 也有 write**,write 是 8 字节指针 + 4 字节时间戳级别的**固定/可预测值**,不是 attacker-chosen 数据。

## 4. 工具价值上限(假设它存在,纯推演)
释放对象所在 cache:**`request_sock_TCP`,objsize 320 B,25 obj/slab,2 pages**(本机 `/proc/slabinfo` 实测);IPv6 另有一个 `request_sock_TCPv6` (320 B)。关键:`# CONFIG_SLAB_MERGE_DEFAULT is not set` ⇒ 该 cache **不与其他同尺寸 cache 自动合并**,uid=2000/app 能塞进这个 cache 的对象**只有 request sock 自身**,attacker-chosen 字节仅限 4-tuple(端口/IP)+ 部分 TCP 选项 ⇒ 达不到"可控非栈 kernel write 原语"的门槛。即便退让谈候选同尺寸(320 B)结构(`sk_buff` head、`msg_msg` 头、`unix_sock` 派生物、`fib6_nodes`(64B)、`tcp_bind_bucket`(128B)):尺寸/flags 不同 + 关合并 ⇒ 无法 cross-cache groom。加上 write 值是 timer base 指针 / jiffies 这类**固定可预测值**、且 `SLAB_FREELIST_RANDOM/HARDENED=y` 使 freelist pointer 随机偏移并加扰——**分级:DoS + 有限 stale read + known-value write**,即比项目已淘汰的"只会写零"那条略好但仍**不可用**,主线不变。

## 5. 最便宜的判别观测(**已在本次任务中执行完毕,零风险**)
