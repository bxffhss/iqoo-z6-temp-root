# 追记 (2026-09-27 更晚): 二分结论作废 + 幽灵存在性尚未证实

## 1. 本轮跑了什么(全部真机, slide 每轮自动重算)

| 轮 | 载荷 | 结果 |
|---|---|---|
| A | 整窗 64 字全填 120 (=推断的受害者 prio) | **存活**, `sched_setattr` ret=0 |
| B | 字 [0,32)=120, [32,64)=0 | **存活** ret=0 |
| C | 字 [32,64)=120, [0,32)=0 | **炸**(重启) |
| D | 精确偏移: `i = j + 0x88`, prio=119, lock=FAKE_LOCK(uts+0x20), right=T(uts+0x38) | **存活 ret=0, 但 init_uts_ns 一个字节都没变** |
| E | 0x50 周期"平铺"版(把同一份假 waiter 平铺 4 份) | 炸 |

D 轮之后读 `uname()` 的 sysname/nodename 原始字节: 与 punch 前完全一致, 观察线程也没有任何
[LEAK] 记录 ⇒ **链走没有走到 [7] 的 `rb_erase`**(那里必写 `*root = T` = sysname[0x24], 肉眼可见)。

## 2. 因此必须作废两条结论

- **作废**: "prio 字 = 窗口第 25 字(偏移 0x88) 由二分证实"。
  二分的判据"炸 ⇔ prio 字不在探针区"是**错的**: 把某些字填 0 之后, 炸的原因可以是
  `lock`/`pc` 读到 0 之类的无效指针, 与 prio 字的位置无关 ⇒ C 轮的"命中"是假阳性。
  只有 A/B(存活)是干净信号, 它们只说明"存在某个使链走早退的填充"。
- **作废**: "覆盖层已经真机证实盖住 waiter"。A/B 两轮同样能被"根本没有幽灵
  (`task->pi_blocked_on == NULL` ⇒ [3] 之前 `if (!waiter) goto out`) 所以任何载荷都不起作用"
  这一假设解释 ⇒ 目前的正/负样本对"载荷是否被读"是**欠定的**。

(不变的部分: `rt_sigreturn` 帧→内核栈的 0x210 字节拷贝路径本身是反汇编坐实的, 且 E 轮证明
"填了什么就会被读到并导致炸" —— 也就是覆盖层**确实在写内核栈**, 只是**写到的位置是不是那个
悬空 waiter** 还没证。D 轮不写不炸, 更像是"没有幽灵可读"。)

## 3. 下一步(必须先做, 别急着继续拼载荷): 直接判定幽灵是否存在

假设 H1 = "本机走超时路径时 `futex_wait_requeue_pi` 会**自己**入链(`task_blocks_on_rt_mutex`)
并在失败时 `remove_waiter(current==自己)` ⇒ pi_blocked_on 被正常清掉 ⇒ 没有幽灵";
H2 = "requeuer 的 proxy-lock EDEADLK 回滚留下幽灵"。

A/B/C/D 与 H1 相容, 与 H2 需要解释"D 为什么不写"。判定实验(便宜, 一次搞定):

1. **让载荷里带一个"必定可见且必定安全"的标记写**: 把 `tree.right` 指到 uts 零洞、
   `tree.pc` 指到**另一个 uts 零洞里的假父节点**(parent!=NULL 分支 ⇒ 会写 `*parent+8 = child`,
   完全落在我们自己可读的 sysname 里)。若 D 轮那种"lock=零洞"没写, 而这一版写了 ⇒ 之前是
   prio 值不对导致早退; 若仍不写 ⇒ 强烈指向 H1(无幽灵)。
2. **同时把 prio 填成多个候选值分别跑**: 真实 prio 取决于 W 是否被 pi 提升(nice0=120 /
   nice19=139 / 被提升后仍 120)。用"整窗都填该候选值"的方式做, 命中就早退(存活), 不命中就
   (pc/lock 非零的小整数)炸 ⇒ "存活/炸"在**整窗同值**这个前提下才是干净比特。
3. **换触发方式**: 上游 5.12+ 的触发是 requeue 成功唤醒 sleeper; 5.4 的 `futex_wait_requeue_pi`
   超时后自己入链。⇒ 试**信号打断**(SIGUSR1 ⇒ `ERESTART_RESTARTBLOCK` 重入, 这是我之前
   cm54 里用过的路径)以及**由 owner 调 `FUTEX_UNLOCK_PI` 唤醒**这两条, 看哪条能让
   `pi_blocked_on` 悬空(判据同上: 让链走真正走到 [7])。
